# Caption censoring recovery

Manual replacements use `captionEditingNode.replaceOwnCaptionTrack`. A reservation
blocks concurrent edits and active translations before a temporary VTT is stored.
Cue text is never written to job rows. The worker uploads a text track, waits for
Mux to report it ready, and then removes the temporary storage object.

When censoring is requested, Robots receives the **manual** track as its source.
Mux removes that intermediate track after the censored output uploads successfully.
RoboTube retains the original source until reconciliation verifies that the final
track is ready. Reconciliation then deletes the original, updates the source ID and
revision, invalidates translations, and regenerates caption-derived metadata.

A confirmed error or cancellation exposes two owner-only actions in the existing
native editor and web dialog:

- **Retry censoring** creates a new attempt against the retained manual track.
- **Finish without censoring** asks for confirmation and reconciles the manual
  track as the final replacement without another Robots job.

Both actions use `recoverOwnCaptionCensoring({ muxAssetId, useManualTrack })`.
An atomic state transition prevents two recovery choices from starting together.
The attempt number in Robots passthrough and the current job ID reject late
events from previous attempts. Failed censoring reserves the existing edit until
the owner resolves it; terminal failure still releases the existing Publish gate.

## Unconfirmed external requests

Do not retry a potentially accepted POST blindly. Uploads carry an opaque track
passthrough so the worker can rediscover a track after losing the HTTP response.
Uploads and censor submission have scheduled watchdogs and worker leases.

When upload ingestion is unconfirmed, **Check Mux status** restarts discovery or
readiness checks without another upload. Temporary storage remains available
until ingestion succeeds or cleanup is confirmed. Known Robots jobs retain the
existing polling/status-check workflow. Censor retries and finishing without
censoring are unavailable while submission or polling is uncertain.

For an unknown Robots submission, an operator can use the existing
`releaseUnattachedEditInternal` only after verifying no job started. For a manual
censor submission this transitions to recoverable failure. Confirmed failed
ingestion, abandoned staging, and video deletion clean temporary storage. Neither
recovery action is an undo facility after successful source replacement.

## Verification

`node --experimental-strip-types --test tests/caption-censor-recovery.test.ts`
executes the actual action and mutation handlers with mocked Mux and storage.
It covers readiness, cleanup, retry, manual finish, owner checks, uncertain
requests, stale events, reservations, and source deletion ordering. Live Mux and
device verification require a disposable test asset; the tests make no paid
Robots requests or real track deletions.
